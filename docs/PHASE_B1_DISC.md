## 3. بنية حاويات ARC — مُستخرَجة
`LOAD_U.ARC` (أول بايت):
```
03 00 00 00 | 00 88 01 00 | 08 00 01 00 | 00 80 00 00 | 01 00 01 00 | 00 80 00 00 | 07 00 01 00
count = 3
0x00018800 = 100,352 = حجم الملف بالضبط  (حقل حجم كلي)
معرّفات الأعضاء الظاهرة: 0x00010008 · 0x00010001 · 0x00010007
```
→ جدول أعضاء من 8 بايت لكل عضو، والمعرّفات `0x1000x` مطابقة لما ذكره توثيق الـRecomp
(العضو `0x10001` = أطلس الحوار).

`FONT8X8.ARC`:
```
02 00 00 00 | 00 20 00 00 | 00 00 00 00 | 00 10 00 00 | 01 00 00 00 | 00 02 00 00
count = 2 · 0x00002000 = 8192 (حجم) · 0x00001000 = 4096 · 0x00000200 = 512
```

`MOJIPAT.ARC`:
```
10 00 00 00 | 84 1a 00 00 | 84 1e 00 00 | f0 2b 00 00 | ثم 16 زوج (u16, u16)
count = 16 · إحداثيات/إزاحات 0x1A84 · 0x1E84 · 0x2BF0
```

## 4. بحث النص — نتيجة سلبية مهمة
```
JUNGLE       : 0
Repliforce   : 0
Maverick     : 0
DR. LIGHT    : 0
Light Web    : 0
```
**لا يوجد نص صريح (plaintext) في القرص كله.** إذن النص إما:
- مضغوط (LZSS/LZ77/Huffman) داخل أعضاء ARC، أو
- مُرمَّز بترميز مخصص/مبني على قاموس.

هذا يستبعد أي نهج "ابحث واستبدل بايت" ويفرض فك الضغط أولاً.

## 5. الخطوة التالية (مرتّبة)
1. **تحديد ترميز الحروف**: مقارنة `MOJIPAT.ARC` بأنماط `FONT8X8.ARC` لاستنتاج خريطة بايت⟶غليف.
2. **فك ضغط أعضاء ARC**: اختبار LZSS (متغيرات الإزاحة/الطول) على أعضاء `LOAD_U.ARC` و`ARC/ST*.ARC`
   حتى يظهر نص مقروء — بوابة إثبات إلزامية قبل أي تعديل.
3. **تحديد عضو سجلات الرسائل**: يجب أن يظهر النص المفكوك فيه `JUNGLE`/`Repliforce` باللاتينية
   (لأن المصدر إنجليزي)، ما يعطي عنوان الرسالة وترميزها.
4. **بناء خط عربي**: 28 حرفاً × 4 أشكال + ligatures ≈ 130 خلية، ضمن مساحة الأطلس.
5. **VWF أو شبكة أوسع**، تحديث العرض، إعادة بناء الحاوية، تحديث جدول LBA في ISO.
6. **`.bps`** عبر Flips + إعادة إقلاع على DuckStation.
